# HIVE iOS

iOS app + Rust-FFI core. Includes the Xcode project (generated via `xcodegen`
from `project.yml`), SPM (`Package.swift` + committed `Package.resolved`), the
Rust workspace member (`mobile/ios/rust`), the cross-compile pipeline
(`build.sh`), and the FFI-scaffold preflight
(`preflight/ios_ffi_scaffold_invariants.sh`).

`Sources/HIVEApp/HIVEApp.swift` is a placeholder SwiftUI entry.
`Sources/HIVECore/HIVECore.swift` is the Swift wrapper around the `extern "C"`
Rust symbols. `Sources/HIVESecurity/DeviceSaltHandle.swift` mirrors the Android
opaque-wrapper class, with deinit-zeroize-parity routed through the Rust FFI.

## Invariants (preflight-gated)

`mobile/ios/preflight/ios_permissions_invariants.sh` enforces the
permissions/privacy invariants. Exit 0 = PASS; exit 1 = FAIL with a
`VIOLATION: ...` diagnostic. Structurally parallel to
`mobile/android/preflight/manifest_invariants.sh` — same exit codes, same
diagnostic format, same positional-arg convention.

Active:

- Check 1 — Info.plist usage-description whitelist diff (MUST)
- Check 2 — forbidden usage-description scans (MUST NOT); runs BEFORE check 1
  so FORBIDDEN wins on both-listed typos.
- Check 3 — HIVE.entitlements baseline diff (MUST; keys:
  `application-identifier` + `com.apple.developer.team-identifier`)
- Check 4 — PrivacyInfo.xcprivacy content (MUST; `NSPrivacyTracking=false` +
  empty `NSPrivacyTrackingDomains` + empty `NSPrivacyCollectedDataTypes` +
  `NSPrivacyAccessedAPITypes` present)
- Check 5 — Audit-trail XML comment before each `NSXxxUsageDescription` (MUST)
- Check 8 — `ITSAppUsesNonExemptEncryption` present and `false` (MUST)
- Check 9 — `CFBundleURLTypes` absent or empty (MUST NOT)

Graceful-skip (activates once the target artifact lands):

- Check 6 — CocoaPods `Podfile.lock` + SwiftPM `Package.resolved` +
  Carthage `Cartfile.resolved` forbidden-SDK scan (MUST); activates
  once a dependency-manager lockfile lands.
- Check 7 — Xcode `project.pbxproj` AppTrackingTransparency-framework
  absence (MUST NOT); activates once the Xcode project lands.
- Check 10 — Xcode Organizer Privacy Report required-reason API
  coverage (MUST); activates after `xcodebuild archive`.
- Check 11 — Declared-key↔Swift-source-call-site coverage (MUST); for every
  `NSXxxUsageDescription` in `Info.plist`, scan `mobile/ios/HIVE/**/*.swift`
  for at least one corresponding framework call-site (e.g.,
  `CBCentralManager` for Bluetooth). Activates once Swift sources land.
- Check 12 — Apple privacy reason-code whitelist scan (MUST); every
  `(NSPrivacyAccessedAPIType, reason-code)` pair declared in
  `PrivacyInfo.xcprivacy` MUST be a verbatim line in
  `preflight/apple_privacy_reason_codes.txt` (curated against Apple's
  documented enumeration). Activates once the whitelist file is present AND
  `PrivacyInfo.xcprivacy` declares one or more reason codes.

When those artifacts land, the graceful-skip pathway converts to live
enforcement WITHOUT code change — the file-existence test flips from
absent to present and the rest of the check body runs.

## Parser preference

`/usr/libexec/PlistBuddy` (macOS default) → `plutil` → regex scan of
the raw XML source. All three pathways produce equivalent verdicts on
well-formed plists; the regex fallback is conservative (may over-count
array entries, but still fails-closed on non-empty).

## Audit-trail comment convention

Every `NSXxxUsageDescription` key in `Info.plist` has an immediately-
preceding XML comment that binds the key to its rationale.

Voice: declarative technical sentences, no marketing adjectives
("seamless" / "smart" / "powerful"), no sparkles, no "Powered by ...",
no exclamation points. Parallels the Android `AndroidManifest.xml`
audit-comment style.

## Forward-flags

- **G-1** — `NSPrivacyAccessedAPITypes` array is intentionally EMPTY.
  Populate with VERIFIED reason codes after the first `xcodebuild archive`
  + Xcode Organizer Privacy Report run. Check 12 parses declared codes
  against `preflight/apple_privacy_reason_codes.txt` (curated against Apple's
  documented enumeration).
- **G-2** — `NSBonjourServices` array NOT declared. Add when the libp2p iOS
  mDNS transport configuration is pinned (`_p2p._tcp.local` or a
  HIVE-specific service-type).
- **G-3** — iOS minSDK is iOS 14+ (`SecRandomCopyBytes` baseline). Both
  usage-description keys are supported at the floor.
- **G-4** — Privacy Report must run on a TestFlight build (not the simulator)
  to exercise all required-reason APIs; schedule as a pre-release gate.
- **G-5** — Dependency manager choice (CocoaPods vs SwiftPM) is open; the
  forbidden-SDK preflight handles either (or both).
- **G-6** — iOS background-mode BLE behavior (`UIBackgroundModes:
  bluetooth-central/peripheral`) is deferred; revisit if implementation
  evidence shows foreground-only BLE pair-discovery fails iOS suspension
  timeouts.
- **G-7** — CI signing posture must match the production bundle-ID + team
  identifier to clear the check-3 entitlement scan.

        mobile/ios/HIVE/Info.plist \
        mobile/ios/HIVE/HIVE.entitlements \
        mobile/ios/HIVE/PrivacyInfo.xcprivacy \
        mobile/ios/preflight/ios_info_plist_whitelist.txt \
        mobile/ios/preflight/ios_forbidden_sdks.txt

    mobile/ios/preflight/ios_ffi_scaffold_invariants.sh \
        mobile/ios/project.yml \
        mobile/ios/Package.swift \
        mobile/ios/Package.resolved \
        mobile/ios \
        mobile/ios/preflight/ios_forbidden_sdks.txt

Both gates exit 0 = PASS / 1 = FAIL with a diagnostic. The FFI-scaffold gate
reuses `preflight/ios_forbidden_sdks.txt` for its check 4 (negative scan
against `Package.resolved`).

The permissions-script also reads `preflight/apple_privacy_reason_codes.txt`
relative to its own location (no positional arg); add a `# Source: ...`
header line and bump `# Last verified: <YYYY-MM-DD>` on each refresh.

## Build pipeline

`mobile/ios/build.sh` runs the 7-step cross-compile recipe:

    1. cargo build --release --target aarch64-apple-ios       --locked
    2. cargo build --release --target aarch64-apple-ios-sim   --locked
    3. cargo build --release --target x86_64-apple-ios        --locked
    4. cbindgen --crate hive_mobile_ffi_ios --output Sources/HIVECore/include/hive_core.h
    5. lipo -create <aarch64-sim.a> <x86_64.a> -output build/sim/libhive_core.a
    6. xcodebuild -create-xcframework ... -output Frameworks/hive_core.xcframework
    7. xcodegen generate

End-to-end execution requires a working Apple toolchain (Xcode 16.2+,
xcodegen, cbindgen, cargo with `aarch64-apple-ios` + `aarch64-apple-ios-sim`
+ `x86_64-apple-ios` rustup targets installed). Without those the script
fails with `command not found` — that is expected; live execution requires an
Apple-toolchain CI runner.

The Rust crate at `mobile/ios/rust/` is registered in the root `Cargo.toml`
workspace members alongside `mobile/android/rust/`. Both share Cargo.lock + the
root `[profile.release]`. The Android + iOS crates carry an identical dep set
(cxx 1.0 + zeroize 1.8 + hkdf 0.12 + sha2 0.10). Crate-type differs by platform:
iOS is `["staticlib"]` (consumed via xcframework), Android is `["cdylib"]`
(consumed via JNI loadLibrary).
